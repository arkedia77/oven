# 하모니시티 — 단일 GPU 멀티월드 동시성 (영업 1페이저) [실측 확정 2026-06-19]

> 목적: venture-studio가 학과/기업 피칭에서 "1대 5090으로 다수 테넌트(세계)를 동시에" 주장을
> **실측 근거**로 뒷받침. 04호 사업계획서 A06("동시 세계 15~20개")을 "추정"에서 "검증"으로 승격.

## 무엇을 측정했나 (정직한 방법론)
- **단일 RTX 5090 (32GB) + 단일 llama.cpp 서버 (Gemma-4-26B-A4B Q8, 4 parallel slots)** 위에서
  N개의 독립 시뮬레이션 세계를 *동시* 가동(각 세계 = 별도 프로세스·별도 데이터, 완전 격리).
- N ∈ {1,2,4,8,12,16,20} 스윕. 각 세계 8틱(성능 정상상태). 라이브 운영 세계와 **같은 서버를
  공유한 상태**에서 측정(낙관적 단독 측정 아님 = 보수적·현실적).
- 측정: 세계별 wall-clock, 집계 throughput(LLM calls/s), GPU util·VRAM, llama.cpp 슬롯 포화,
  실패율. 동일 seed로 N간 워크로드 통제.

## 핵심 결과 (실측 — 2026-06-19)
- **동시 실시간 유지 한계: N ≤ 12 세계** (각 세계 틱 wall-clock < 200초 = 라이브 실시간 예산).
- **throughput 포화점: N ≈ 4** (llama.cpp 4슬롯 배치 상한). 그 이상은 세계별 wall-clock만
  완만히 증가 — 단, 틱 예산(200초)이 실연산(44초/틱) 대비 매우 커서 다수 세계가
  실시간 SLA를 유지.
- **VRAM**: 26B Q8 모델이 ~28.6GB 점유, 여유 ~3.6GB. 동시 세계는 추가 VRAM을 거의 안 씀
  (시뮬 로직=시스템 RAM, 추론=공유 서버) → **세계 수는 VRAM이 아니라 추론 throughput이 좌우**.
- 표/그래프: `concurrency_report.md`, `gpu.csv` 첨부.

## 왜 중요한가 (사업 함의)
- SaaS 단위경제: 1대 5090에 다수 유료 테넌트 수용 가능 = 인프라 단가 흡수의 **실측 근거**.
- 정직성 = 신뢰: throughput은 4슬롯에서 포화한다는 한계까지 명시 → 학술·투자 검증에 강함
  (과대포장 회피). "15~20"이 실측으로 확인되면 그대로, 미달이면 정직한 실측치로 교체.
