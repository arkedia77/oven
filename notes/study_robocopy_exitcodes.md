# 스터디 — robocopy 종료 코드와 /MIR·/E·/L (A-177 learning · 10-28 시한 → 11-01 마감, 4일 늦음)

출처: Microsoft Learn «robocopy» 명령 문서 + «Return codes used by Robocopy» 지원 문서(기억 기반 정리 · 원문 재열람 안 함 — 아래 «검증» 줄이 leowin2 실측으로 맞춘 범위).

## 종료 코드 = 비트 합
| 비트 | 뜻 | 우리 판정 |
|---|---|---|
| 0 | 바뀐 것 없음(원본·사본 이미 같음) | OK |
| 1 | 파일 1개 이상 복사됨 | OK |
| 2 | 사본 쪽에만 있는 «여분» 파일·폴더 있음(/MIR 이면 지워짐, /E 면 남음) | OK |
| 4 | 이름은 같고 종류가 다른 «불일치» 항목 있음 | OK(로그 확인 대상) |
| 8 | 재시도(/R) 뒤에도 복사 실패한 항목 있음(잠김 32·권한 5 등) | **FAIL** |
| 16 | 치명 오류 — 아무것도 못 함(원본 없음 오류 2·공유 접근 실패 등) | **FAIL** |

- 합쳐 나온다: 3 = 1+2 · 9 = 1+8(일부 복사됨 + 일부 실패). 그래서 «≥8 = FAIL» 이 맞는 문턱이다.
- 우리 두 스크립트(`infra/leowin_backup.ps1`·`leowin2_backup.ps1`)는 `ok = (rc -lt 8)` — 문서와 일치. 고칠 것 없음.

## 원본 상태별 동작
- **원본 폴더 없음** → 오류 2 → rc 16. 10-26 leowin2 SongFormer_logs=16 이 이것(내가 10-25 원본을 지움). 수리 = Test-Path skip(3d3bd33).
- **원본이 비어 있음(폴더는 있음)** → /MIR 는 사본을 비운다(rc 2 류 · OK 로 보임). /E 는 사본을 남긴다. ⇒ «빈 원본 = 성공 줄» 이라 결과 줄로는 못 잡는다. C:\RVC·so-vits 가 이 상태(10-26 의도적 · 보관본 = `_archive\voice_20261026`).
- **/L** = 목록만(복사·삭제 0). DryRun 판정에 쓰는 것 · rc 는 «했다면 무엇이 바뀌었을지»를 같은 비트로 낸다.

## 판단(㉡ 질문의 답)
- manifest 에 잡별 rc 해석표를 **두지 않는다** — 문턱(≥8)은 스크립트가 이미 맞게 쓰고, 표는 이 노트 1장이면 충분. manifest 에는 이 파일 포인터만.
- 대신 남는 사각지대 1개: **/MIR 잡의 원본이 «비어서» 사본이 지워지는 경우**는 OK 로 찍힌다. 막는 방법(파일 수 0 이면 /MIR 건너뜀)은 RVC·so-vits 처럼 의도적으로 비운 잡과 충돌 → 지금은 넣지 않고, 원본을 비우는 정리 때 메모리 규칙(삭제 전 백업 잡 대조)으로 막는다.
