# Gemma4-12B agentic PoC — 샘플러 민감도 측정 (temp 1.0 vs 0.3)

작성: 2026-08-04 (oven) · 근거: A-089 kee 승인 조건 3
★**라벨 주의**: 본 측정의 이름은 **「샘플러 민감도 측정」**이지 **「제작자 주장 재현」이 아니다.**
제작자 권장값을 이탈한 판이 섞이므로 두 판을 **같은 표의 다른 행**으로 두고 **각 행에 조건을 병기**한다.

---

## 0. 왜 쟀는가

2026-08-02 PoC에서 「우리가 실제로 하는 일」(로그 진단 4단)로 재측정했을 때 **5스텝 내내 도구만
반복하고 결론에 도달하지 못했다.** 제작자가 **「이슈 99%는 샘플러 설정」**이라 고지했으므로,
**「모델이 못 한다」와 「샘플러 탓이다」가 교락된 채로 남는 것**을 피하기 위해 갈랐다(kee 판정).

## 1. 측정 설계 — 무엇을 통제했는가

| 통제 축 | 처리 |
|---|---|
| 시나리오·도구 스키마·시스템/유저 프롬프트 | 08-02 `poc_logdiag.py`와 **동일**(파일 그대로 파생) |
| `max_tokens` / 최대 스텝 | 700 / 5 — **동일** |
| 도구 응답 | 전부 **실측치 고정**(가공 수치 아님) — **동일** |
| **temperature** | **1.0 / 0.3** ← 처치 변수 |
| **threads** | ★**4로 통일** |
| seed | 42 / 7 / 123 (조건당 3판) |

★**threads를 통일한 이유**: kee 조건 ⑵가 「PoC 스레드 10→4」였는데, 08-02 판은 threads 10이었다.
그대로 비교하면 **온도와 스레드가 교락**된다. ⇒ **threads 4에서 두 온도를 모두** 돌리고,
08-02 판은 **역사행으로만** 인용한다.

★**시드 3개를 쓴 이유**: 표본 1판으로 판정하지 않기 위함(A-042에서 얻은 「다seed 원칙」 자기 적용).

원자료: `results/logdiag_t{10,03}_s{42,7,123}.json` (스텝별 도구명·인자 전문 포함)

### 갈린 것

- **스키마 밖 인자 발명**: temp 1.0 **3판 중 2판** → temp 0.3 **3판 중 0판**
- **같은 도구 연속 반복(퇴행 루프)**: temp 1.0 최대 3 → temp 0.3 최대 **4~5** (B1은 `get_llm_server_props`를 **5연속**)

### 안 갈린 것

- **결론 도달: 0/3 vs 0/3.** 두 온도 모두 **6판 전부 5스텝 내 결론 없음.**
- **받은 데이터 미사용: 6/6.** ★**모든 판이 `get_llm_server_props`를 최소 1회 호출해
  `n_ctx_per_slot=2048, total_slots=4`(= 실제 근본 원인)를 손에 넣었고, 그것을 결론으로 옮긴 판은 없다.**

## 3. 판정 — 경계를 지킨다

> kee 지정: 통과 = 「샘플러 설정으로 갈린다」**까지**, 실패 = 「이 시나리오에서는 샘플러로
> 안 갈린다」**까지**. **어느 쪽도 「쓸 만하다 / 못 쓴다」로 확대 금지.**

**판정: 「이 시나리오에서는 샘플러(temperature)로 결론 도달 여부가 갈리지 않는다.」**

부기 1건 — **실패의 「양상」은 갈렸다.** 온도를 낮추면 **인자 발명은 사라졌고**, 대신
**같은 호출을 더 오래 반복**했다. 즉 **표면적 형식 오류는 샘플러에 민감하고, 수렴 실패는 아니다.**

★이는 kimsecretary가 08-04에 낸 판독 — 「실패 4종 중 **④받은 데이터 미사용이 가장 무거운 신호**,
①~③은 프롬프트·샘플러로 개선 여지가 있으나 ④는 다르다」 — 과 **일치하는 방향**이다.
①은 실제로 샘플러로 사라졌고 ④는 6/6 그대로였다.

### 이 측정이 말하지 않는 것 (확대 금지 목록)

- 「Gemma4-12B가 쓸 만하다/못 쓴다」 — **말하지 않는다.** 시나리오 1종·스텝 상한 5·조건당 3판.
- 「다른 온도·다른 샘플러(top_p, min_p 등)에서도 안 갈린다」 — **안 쟀다.**
- 「스텝 상한을 늘리면 결론에 도달한다/못 한다」 — **안 쟀다.** 6판 모두 상한 5에서 끊겼으므로
  **상한이 구속력을 가졌는지 자체가 미확인**이다.
- 「단순 도구 호출(2단)도 실패한다」 — **아니다.** 08-02에서 2단 시나리오는 통과했다.
  이번 실패는 **다단 자율 진단** 한정이다.

## 4. 재현 방법

```
# 서버(ogo, CPU 전용 — GPU는 하모니시티가 점유하므로 --device none 필수)
D:\llama.cpp\bin\llama-server.exe --model D:\llama.cpp\models\gemma4-v2-Q4_K_M.gguf ^
  --port 8090 --host 127.0.0.1 --ctx-size 8192 --device none --n-gpu-layers 0 ^
  --threads 4 --jinja --temp 1.0 --repeat-penalty 1.1

# 측정
python poc_logdiag_temp.py --temp 1.0 --seed 42 --out results/logdiag_t10_s42.json
python poc_logdiag_temp.py --temp 0.3 --seed 42 --out results/logdiag_t03_s42.json
```
※ temperature는 요청 파라미터로 덮어쓰므로 서버 `--temp`는 무관하다. `--threads`만 서버 플래그다.

## ★ v1 정정 고지 (2026-08-05 · A-105 L2 심사 조건 반영)

본 문서의 판독 중 **2건이 정정**됐다. 정본은 **`A105_판정문_v1.md`**이며 아래 요지만 남긴다.

1. ★**「받았다는 사실 자체를 부정한다」 철회** — 원문에 한정어가 있었다(`anywhere **in them**`=grep이 돌려준 버킷 / `by searching **these lines**`). ⇒ **모델의 문장은 참이었고**, 한정어를 지운 인용이 없는 주장을 만들었다. 판정 「④ 받은 데이터 미사용」은 유효하고, 문면은 **「수령한 값을 결론에 쓰지 않고 grep 경로만 반복 탐색」**으로 낮춘다.
2. ★**3안 논거 축 교체** — 「마커 누출이 유력하므로 미룬다」 → **「인과가 미확정이므로 가역·저비용 검증이 비가역·고비용 조치에 선행한다」**. 미확정을 유리한 쪽으로 읽은 것이 오류였다.
3. 판정 경계는 **「이 시나리오·이 셋업에서는」**으로 한 겹 좁힌다(표본 시나리오 1종).

> 판별선: **「한정어를 지운 인용은 다른 주장이 된다」** — 커지는 방향의 오독은 결론을 강하게 만들어 **저자 본인이 검산할 동기가 가장 약한 자리**다.
